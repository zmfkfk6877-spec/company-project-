## 자동 테스트 범위

- 50개 독자적 제목, 정상 20/피싱 30, 중복 없는 출제, 10개 블록 난이도 3/4/3 및 정상 4/피싱 6
- 비율이 불가능한 경우 임의 완화 없이 출제 거절
- 공개 문제 필드에 정답/해설/점수 누락
- 점수 → 반올림 전 정확도 → 정답수 → 총 응답시간 → 고정 응시 ID 순위
- AES-GCM 복호화·변조 거절, 정규화 HMAC 중복 식별, CSV 수식 방지
- 운영시간 전/후 차단, 동의 없으면 등록 거절, 서버 시작시각+300초
- 새로고침/시작 재호출 시 기존 문제·만료시각 유지
- 유효하지만 다른 참가자의 배정 문제, 임의 ID, 아직 표시되지 않은 문제 거절
- 동시 답안 재전송 한 번만 채점, 오답 감점, 서버 만료 후 추가 응답 차단
- 다른 결과 ID 직접 호출 거부·다른 세션의 결과 조회 격리
- 완료 후 중복 참여 차단, 관리자 초기화 후 기록·세션 삭제
- 대회 CRUD 입력 비율/날짜 검사, 문제 CRUD·복사, 배정 스냅샷 보존
- 마스킹 검색·CSV 전체값 접근, 다운로드 감사로그
- 종료 및 해설 공개 설정 모두 충족해야 개인 해설 접근
- 미인증·CSRF·잘못된 관리자 로그인 거절, VIEWER/OPERATOR 권한 구분
- DB 공통 요청 제한 및 기간 만료 후 초기화
- 보유기간이 지난 이벤트의 개인정보 삭제, 최근 이벤트 보존, 정리 감사로그
- 설정된 추가 응시 허용 및 최대 횟수 제한

시간초과 테스트는 서버 DB의 expiresAt을 지난 시각으로 설정해 실행했습니다. 실제 5분 동안 기다린 테스트는 아니며, 서버 만료 판단과 복원 경로를 검증합니다. 100명 테스트는 DB/서비스 동시성 검사이며 외부 네트워크의 지속 부하·최대 처리량 보증은 아닙니다.

## 해결한 환경 문제

npm/Prisma의 기본 캐시 경로가 읽기 전용이어서 npm 캐시를 `/tmp/phishing-npm-cache`, Prisma 캐시를 `/workspace/.cache`로 옮겼습니다. Prisma 공식 엔진은 검증을 유지하여 생성했습니다. Docker 빌드 중 디스크가 가득 차 테스트 DB의 migration이 실패한 것은 미사용 빌드 캐시·이전 이미지 정리 후 빈 테스트 DB만 초기화하여 해결했습니다. 개발 DB는 재시작·복구 후 브라우저 검증을 다시 통과했습니다. 테스트 전용 Compose 컨테이너·볼륨은 검증 후 삭제했고 개발 DB·앱은 유지했습니다.

일반 소스 Docker 빌드는 이 클라우드의 Alpine 패키지 다운로드 정책(403) 때문에 완료하지 못했습니다. 검증한 대체 경로는 `Dockerfile.prebuilt` / `compose.prebuilt.yaml`입니다. TLS·체크섬·패키지 서명 검증을 끄지 않았습니다. 참고 사이트도 접근 정책 때문에 직접 열람하지 못했으며 제공된 HTML의 UX 아이디어와 명세를 토대로 독자적으로 제작했습니다.

## 운영 전 외부 설정 및 미검증 항목

- 실제 기관 서버에 HTTPS 인증서, 도메인, PUBLIC_URL, secure cookie, 관리자 IP/VPN 설정 적용
- 실제 서버에서 백업 파일 복원·키 복원·이미지 볼륨 복원 훈련
- 기관 네트워크 및 장시간 동시사용 부하 검증
- 보유기간 정리 스크립트를 기관 스케줄러에서 매일 실행
- 실명 인증이 필요하면 기관 SSO/사번 인증 연동, 관리자 MFA는 향후 확장
- 환경 초안 저장과 환경 게시·새 작업 복원 검증은 별개: 게시 및 새 작업 복원은 아직 수행하지 않음

Git 저장소가 최초에는 커밋 없는 빈 상태였으므로 파일은 생성된 작업 파일로 남겨두었습니다. 자동 커밋·push·외부 배포는 수행하지 않았습니다.
